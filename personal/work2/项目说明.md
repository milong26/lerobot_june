## 一、项目概述

### 研究目标

研究**单任务微调时，什么样的示范数据分布能让成功率最高**。

在Meta-World环境的`pick-place-v3`任务上，使用ACT策略进行单任务微调，探究不同的示范数据采集策略（均匀随机、规则网格、边界偏向、距离分层等）对最终策略成功率的影响。

### 核心问题

- **评测分布是固定的**：`MetaworldEnv`每次`reset()`都在整个合法初始状态空间里做无种子随机采样
- **你能控制的只有数据分布D**：给定同一个expert policy和总预算，D里的`(obj_pos, goal_pos)`应该长什么分布，才能让期望成功率最大？
- **本质**：数据覆盖 vs 数据密度的权衡问题

### 关键结论

1. 原有`collect_metaworld_dataset.py`只能靠换seed间接影响物体/目标位置，做不到精确指定坐标
2. 39维`observation.environment_state`的解读有一处实质性错误（已修正）
3. 需要一个**固定评测集**才能做不同数据配方之间的公平对比
4. 已建立完整的"生成→训练→评测→分析"实验链路

### 4.1 mw_common/ — 共享工具包

#### obs_utils.py — 39维观测解析（修正版）

| 切片 | 含义 | 备注 |
|---|---|---|
| `[0:3]` | 末端执行器位置xyz | |
| `[3]` | 夹爪开合度 | |
| `[4:7]` | **物体1位置xyz** | |
| `[7:11]` | 物体1四元数朝向 | **不是"目标位置"** |
| `[11:14]` | 物体2位置（单物体任务为0） | |
| `[14:18]` | 物体2四元数（为0） | |
| `[18:36]` | **上一帧frame-stack** | **不是"one-hot任务向量"** |
| `[36:39]` | **目标位置xyz** | |

**关键函数**：
- `obj_pos(env_state)` — 提取物体位置
- `goal_pos(env_state)` — 提取目标位置
- `find_task_index(dataset_meta, task_desc)` — 按任务描述匹配索引

#### state_injection.py — 状态注入器

**核心能力**：通过monkeypatch强制指定任意`(obj_pos, goal_pos)`

**关键函数**：
- `make_env_with_fixed_state(task_name, rand_vec, ...)` — 创建固定状态环境
- `validate_pick_place_pair(obj_xy, goal_xy, min_dist=0.15)` — 验证状态合法性

**使用示例**：
```python
from personal.work2.mw_common.state_injection import make_env_with_fixed_state
```

## 八、常见问题

### Q1: 为什么需要固定评测集？

因为`MetaworldEnv`每次`reset()`都用全局无种子随机采样，不同数据配方之间对比成功率时，跑两次会得到两个不可比的随机样本。固定评测集确保所有配方在**相同的200个状态**上测试。

### Q2: 为什么要移除`observation.environment_state`？

因为39维environment_state包含物体位置和目标位置等特权信息。如果不移除，策略可能直接"作弊"。

### Q3: `--require-success`为什么默认开启？

因为如果刻意采样"困难区域"，expert有一定概率失败。失败的示范会污染训练集。

### Q4: 断点续采怎么用？

直接再次运行`generate_dataset.py`，指向同一个`--output-dir`。脚本会自动加载已有数据集并追加。

### Q5: 如何指定GPU？

使用`CUDA_VISIBLE_DEVICES`环境变量：

```bash
CUDA_VISIBLE_DEVICES=0 python personal/work2/generate_dataset.py ...
CUDA_VISIBLE_DEVICES=0,1 lerobot-train ...
```
